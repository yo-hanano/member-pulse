# MemberPulse 要件棚卸し

この文書は、`monthly-review-saas-plan.md` と `phase-0-schema-and-beta-plan.md` を具体化する前に、出てきた要件を領域別に整理するための棚卸しメモ。

現時点の方針は、`markeman` 的な収支計画とメディアプラン、`alcos-portal` 的な CRM / 会員管理、MemberPulse 固有の月次レビューと拠点別 PL を組み合わせること。

## 1. 全体方針

MemberPulse は、日常運営システムの全面置き換えではなく、月次経営レビューに必要な計画と実績を扱う。

責務は次に分ける。

- 初期セットアップ: 会員プランと販管費項目を確認・調整する
- CRM 実績: 会員、リード、契約、売上、入退会の実績を拾う
- 収支計画: 全社または拠点別の売上、利益、会員数、費用、広告計画を作る
- メディアプラン: どのスコープ、どの会員種別、どのチャネルに投資するかを計画する
- 月次レビュー: 計画と実績を突き合わせ、重要成功要因と来月アクションを出す
- 拠点別 PL: 撤退、移転、追加投資の判断に使う

## 2. 優先度区分

- Phase 0 初期: mock UI と最低限の DB / API で検証する
- Phase 0 後半: beta に入る前、または beta 中に追加する
- beta: 実ユーザーの入力を見てから判断する
- 後回し: 初期価値に直結しないため作らない

## 3. 初期セットアップ

初期セットアップは、収支計画そのものではなく、収支計画と CRM で使うマスタの確認・調整に寄せる。事業者名、業種、決算月は admin の会社発行時に初期作成し、ユーザーは自社情報画面で変更する。

Phase 0 初期:

- 会員種別 / 会員プラン
- 利用する販管費項目
- テンプレートにない独自販管費項目の追加
- 変動費の連動項目選択: 売上 / 会員数 / 新規入会数 / 問い合わせ数 / 体験数 / 拠点数 / スタッフ数
- 光熱費など自動計算しにくい費用は、連動項目ではなく手入力 / 固定額として扱う
- 手入力で始めるか、CRM 実績を使うかの選択

Phase 0 後半:

- 必要になった時点での最初の拠点追加
- 複数拠点の追加
- エリア / 都道府県の設定
- 費用項目のスコープ設定
- 固定費 / 変動費 / 本部費用の分類
- 会員プランの基準月額、利用回数、対象区分

beta:

- 業種別の初期テンプレート
- 既存データからのマスタ候補作成
- セットアップ進捗の再開

後回し:

- 予約枠設定
- 請求設定
- 決済設定
- 出席管理設定

## 4. マスタ

収支計画と月次レビューで使う選択肢を先に整備する。

admin の会社発行時点で作るもの:

- `company`: 会社 ID / company code を含む認証・契約上の組織
- 初期管理者 `employee`
- 初期管理者への招待または初期ログイン手段
- `business_profile`: 事業者名、業種、決算月などの自社情報
- 業種に応じた販管費テンプレート候補

admin が共通マスタとして管理するもの:

- `cost_item_template`: 業種別の販管費テンプレート
- 将来的な会員プランテンプレート
- 将来的な集客チャネルテンプレート

ユーザーが初期導線で確認・調整するもの:

Phase 0 初期:

- `membership_plan`: 会員種別 / 会員プラン
- `cost_item_template`: 費用テンプレート
- `cost_item`: 利用する販管費項目。固定費 / 変動費、費用スコープ、変動費の連動項目を持つ

Phase 0 後半:

- `location`: 拠点
- `area`: 管理エリア
- 都道府県スコープ
- 集客チャネル
- 費用スコープ: `company` / `area` / `prefecture` / `location` / `head_office`
- 広告スコープ: `company` / `area` / `prefecture` / `location` / `membership_plan`

beta:

- 会員種別の業種別テンプレート
- 販管費テンプレートの業種別調整
- 集客チャネルのテンプレート

後回し:

- 細かい勘定科目管理
- 会計ソフト連携
- 媒体別の詳細入稿管理

## 5. CRM 実績

CRM は収支計画の代替ではなく、月次レビューで実績を拾うための土台。

Phase 0 初期:

- `lead`: 問い合わせ
- `trial_session`: 体験予約 / 体験実施
- `member`: 会員
- `membership_subscription`: 会員のプラン契約履歴
- lead から member への入会変換
- 月謝売上の算出に使う契約月額
- 入会日、退会日、休会状態

Phase 0 後半:

- リード流入元
- 拠点別リード
- 会員種別別の契約履歴
- その他売上
- 退会理由

beta:

- CSV インポート
- 外部予約システムや会員管理システムからの取り込み
- CRM 実績から収支計画の初期値補完

後回し:

- 日次の出席管理
- 振替管理
- 請求書発行
- 決済回収

## 6. 収支計画

収支計画は `markeman` の Plan / PlanSim に近い。まず全社計画を作り、必要になった時に拠点別目標を追加できる構造にしておく。

Phase 0 初期:

- 全社の年間売上目標
- 全社の年間営業利益目標
- 全社の年度末会員数目標
- 会員グループ別の現在会員数
- 会員グループ別の平均月謝
- 会員グループ別の月次退会率
- 会員グループ別の月間入会数
- 固定費、変動費、本部経費
- 変動費の計算ドライバー: 売上 / 会員数 / 新規入会数 / 問い合わせ数 / 体験数 / 拠点数 / スタッフ数
- 水道光熱費など月ごとにブレるが式で出しにくい費用は、月別手入力または固定額として扱う
- 年間広告費または月間広告費
- 成り行き
- GAP 調整
- 計画保存

Phase 0 後半:

- 最初の拠点追加
- 拠点別目標
- 拠点別の会員グループ構成
- 拠点別の販管費計画
- 拠点別の広告費計画
- 全社目標から拠点別目標への簡易按分
- 拠点別目標合計と全社目標の差分警告

beta:

- 拠点別目標の手動調整 UI
- 店舗ごとの投資方針設定
- 撤退判断ラインの設定
- 複数計画シナリオ

後回し:

- 複雑な月別季節変動
- 日次着地予測
- 自動最適化

後回し:

## 12. 次の進め方

まずは Phase 0 初期の中でも、収支計画 mock UI と要件の整合を優先する。

次に行うこと:

1. 初期セットアップをマスタ整備画面として再定義する
2. 収支計画 mock から初期セットアップ項目を外す
3. 収支計画に会員グループ、費用、広告、メディアプランの最小入力を残す
4. 拠点別目標は最初は全社計画からの簡易按分で扱う
5. DB スキーマに落とす前に、`goal_plan_media` の採否を決める

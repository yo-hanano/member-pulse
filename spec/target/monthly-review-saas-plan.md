## 1. 指標定義

### 1.1 ファネル KPI

画面上は CVR という表現よりも業務用語を優先する。

- 体験予約率: 体験予約数 ÷ 問い合わせ数
- 体験実施率: 体験実施数 ÷ 体験予約数
- 入会率: 入会数 ÷ 体験実施数
- 問い合わせ入会率: 入会数 ÷ 問い合わせ数

問い合わせは、体験予約前の見込み客接点と定義する。Web フォーム、LINE 問い合わせ、電話、Instagram DM、店頭問い合わせ、紹介経由の連絡を含める。体験予約だけが直接入る導線では、問い合わせ数 = 体験予約数として扱えるようにする。

実績がない場合の初期 CVR は次の通り。

- 問い合わせ → 体験予約率: 70%
- 体験予約 → 体験実施率: 80%
- 体験実施 → 入会率: 50%
- 問い合わせ → 入会率: 28%

想定 CVR は、過去 3 か月実績を優先し、実績がなければ初期値を使う。ユーザーは目標 CVR を上書きできる。

### 1.2 広告 KPI

- CPA: 広告費 ÷ 問い合わせ数
- CPO: 広告費 ÷ 入会数

### 1.3 退会率と LTV

- 月次退会率: 退会数 ÷ 月初会員数
- LTV 計算用退会率: 直近 3 か月平均退会率
- 退会率下限: 1%（退会率が低すぎる場合のノイズ防御）
- 許容退会率の初期値: 月次 3%（ユーザー上書き可）
- 平均継続月数: 1 ÷ LTV 計算用退会率
- 月謝 1 会員あたり粗利: 平均月謝 - 会員連動変動費 - 月謝売上率連動変動費
- 粗利 LTV: 月謝 1 会員あたり粗利 × 平均継続月数
- 限界 CPO: 粗利 LTV × 許容広告投資率

限界 CPO 判定は、実績 CPO ÷ 限界 CPO で行う。

- 安全: 70% 以下
- 注意: 70% 超〜100%
- 危険: 100% 超

固定費や本部経費は、限界 CPO には含めない。広告で 1 人増えたときの獲得許容額は、まずその会員が生む月次粗利と継続月数で見る。固定費や本部経費は、PL と利益率で別途判断する。

### 1.4 休会の扱い

休会者は集計上、在籍会員と分ける。

- 月末会員数の内訳に表示する
- LTV 計算の退会数には含めない
- 月謝売上には含めない。休会費がある場合だけ含める

## 2. PL 設計

### 2.1 位置づけ

PL は経営判断用の簡易 PL とする。会計ソフトの代替にはしない。

扱わないもの: 仕訳、税務申告、消費税計算、決算書作成、銀行連携、会計ソフト連携、厳密な勘定科目管理。

簡易 PL で答える判断は次の通り。

- 売上未達なのか
- 広告費を増やす余地があるのか
- 人件費率が高すぎるのか
- 固定費に対して在籍数が足りないのか
- 利益を残すには単価を上げるべきか
- 集客より退会抑制を優先すべきか

### 2.2 費用区分

- 広告費
- 拠点直接変動費
- 拠点直接固定費
- 本部経費

変動費・固定費は `cost_item` マスタに登録し、月次 PL に反映する。

変動費マスタの計算方式:

- 売上率: 月謝売上または総売上 × n%
- 会員数連動: 月末会員数 × n 円
- 実績入力: 月次で金額を直接入力

固定費マスタは、家賃、システム固定費、保険、税理士費用などの毎月発生する費用を登録し、月次入力では必要に応じて上書きする。

本部経費は売上比率で拠点別に按分する。

### 2.3 全体 PL

売上、粗利、営業利益の段階で表示する。

- 総売上
  - 月謝売上
  - その他売上
- 変動費
- 粗利
- 広告費
- 固定費
- 本部経費
- 営業利益

広告費は営業利益計算に含める。ただし広告費は CPA / CPO / LTV / 限界 CPO 判断の主役でもあるため、広告 KPI セクションでも独立表示する。PL と広告 KPI で同じ広告費を二重計上しない。

### 2.4 拠点別 PL

拠点別 PL は、月次レビュー内の 1 セクションとして扱う。独立した PL 分析画面は当面作らない。

比較テーブルの列:

- 拠点名 / 売上 / 広告費 / 変動費 / 固定費 / 直接利益 / 本部経費配賦 / 配賦後営業利益 / 利益率 / CPO / 限界 CPO / 月末会員数 / 入会数 / 退会数

本部経費配賦は、通常表示では配賦額と配賦後営業利益を見せ、計算根拠（拠点売上・全体売上・売上構成比・本部経費総額・配賦額）は行の展開表示にする。

要約カードは、問題のある拠点だけ最大 3 件表示する。要約対象:

- 配賦後営業利益が赤字
- 利益率が目標未達
- CPO が限界 CPO 超過
- 退会率が許容退会率超過
- 会員数が目標未達
- 前月比で利益が大きく悪化

拠点別広告費の扱い:

- 拠点指定広告費: その拠点へ直接計上
- 拠点未指定広告費: 本部広告費として売上比率で配賦
- 全体 PL: すべての広告費を合算
- 拠点別 PL: 直接広告費 + 配賦広告費

拠点別限界 CPO は、拠点別の月謝 1 会員あたり粗利をベースに計算する。

```text
拠点別月謝 1 会員あたり粗利
  = 拠点平均月謝 - 拠点会員連動変動費 - 拠点月謝売上率連動変動費

拠点別粗利 LTV
  = 拠点別月謝 1 会員あたり粗利 × 拠点別平均継続月数

拠点別限界 CPO
  = 拠点別粗利 LTV × 許容広告投資率
```

## 3. 収支計画（目標設定と KPI 逆算）

### 3.1 初期入力項目

年間目標と簡単な前提から月別目標を自動生成する。必要に応じて月別上書きできる。

- 年間売上目標
- 年間営業利益目標
- 年度末会員数目標
- 現在会員数
- 平均月謝
- 許容退会率
- 想定 CVR
- 広告費上限
- 許容広告投資率

### 3.2 逆算ロジック

月別の会員数目標は、現在会員数から年度末会員数まで線形に増やす。

```text
月別目標月末会員数
  = 現在会員数 + (年度末会員数 - 現在会員数) × 経過月数 / 残月数
```

目標入会数は、目標純増数と許容退会数から逆算する。端数は切り上げる。

```text
目標純増数 = 当月目標月末会員数 - 前月目標月末会員数
許容退会数 = 前月目標月末会員数 × 許容退会率
目標入会数 = 目標純増数 + 許容退会数
```

目標問い合わせ数は、目標入会数と想定 CVR から逆算する。

```text
目標問い合わせ数 = 目標入会数 ÷ (体験予約率 × 体験実施率 × 入会率)
```

月別売上目標は、月謝売上を会員数と平均月謝から作り、年間売上目標との差分をその他売上に配分する。

```text
月謝売上目標 = 月別目標月末会員数 × 平均月謝
その他売上年間目標 = max(0, 年間売上目標 - 年間月謝売上目標)
その他売上月別目標 = その他売上年間目標 ÷ 12
```

年間売上目標が年間月謝売上目標を下回る場合は、入力前提が矛盾しているため警告を出す。

月別営業利益目標は、年間営業利益目標を 12 等分する。広告費上限は次の通り。

```text
月別広告費上限 = 年間広告費上限 ÷ 12
採算広告費上限 = 目標入会数 × 限界 CPO
実務上の広告費目安 = min(月別広告費上限, 採算広告費上限)
```

### 3.3 収支計画 UI の要点

`financial-plans/setting` は、1 画面上で「計画グループ」「売上関連」「経費関連」「着地」を上から順に確認できる構成にする（markeman のオファー設定を画面原型に、用語を会員制向けに置換）。

- 計画グループ: 期間、売上目標、営業利益目標、期末会員数目標
- 現状数値: 料金プラン別の在籍・単価前提と獲得ファネルを Drawer で入力。実績があれば `membership_plan` / `membership_subscription` / CRM 実績から初期値を取得
- リード・入会計画: 問い合わせ数/月を起点に、体験予約数 → 体験実施数 → 入会数 → 月謝売上を逆算表示
- 費用計画: 登録済み `cost_item` をもとに、月額固定費・本部経費・変動費率・月額広告費
- 着地: 月次の売上、営業利益、会員数、入会数、問い合わせ数 + 目標比のライブ試算

グリッド入力（現状数値・リード入会計画）は AG Grid Community + TSV paste 自前実装とし、Excel / Google Sheets からの貼り付けを重視する。

## 4. 月次実績入力と二層構造

### 4.1 二層構造（台帳とレビューの関係）

台帳（CRM・売上台帳）からの自動集計は**参考値**、月次レビューの**手入力値が最終的な正**とする。

- CRM 集計値: 参考表示
- 今回の入力値: 初期値として CRM 集計値をコピー
- ユーザー上書き: 可能
- 差分がある場合: 警告のみ表示（保存は妨げない）

台帳から集計する対象: 問い合わせ数、体験予約数、体験実施数、入会数、月末会員数、平均月謝、月謝売上・その他売上（売上台帳）。

### 4.2 最小入力項目

- 月初会員数（前月末から自動設定）
- 月末会員数（主入力）
- 新規問い合わせ数 / 体験予約数 / 体験実施数 / 入会数 / 退会数
- 総売上 / 月謝売上 / その他売上 / 平均月謝
- 広告費（全体 / 拠点別）
- 変動費 / 固定費 / 本部経費

月初会員数 + 入会数 - 退会数 と月末会員数が合わない場合は警告のみ出す。入力保存は妨げない。

### 4.3 入力支援

- 前月値コピー
- 概算入力・未確定フラグ
- 平均月謝と在籍数から売上を概算
- 入会数・退会数から在籍数を補助計算
- 問い合わせ数が不明な場合は未計測として扱い、次月から計測対象にする

### 4.4 退会理由マスタ

退会理由は選択式 + メモで持つ。初期候補:

料金 / 通う時間がない / 効果を感じない / 予約が取りにくい / 拠点・立地 / インストラクター相性 / 体調 / 引っ越し / 他社へ移行 / 不明 / その他

## 5. 月次レビューの状態管理とスナップショット

### 5.1 入力ウィザード

収支計画と CRM 実績を突き合わせるウィザードにする。

1. 対象月と拠点選択
2. 計画値確認
3. CRM 実績値確認
4. 会員数の補正
5. 集客実績の補正
6. 売上、広告費、費用の補正
7. 確認（自動計算 KPI と警告、主要 KPI と予実差分を先に見せる）
8. レポート生成

必要な UX: ステップ間の自動保存、CRM 実績値の「反映」ボタン、計画値・CRM 実績値・手入力値の区別表示、不整合はブロックせず警告、未確定値フラグ。

### 5.2 状態遷移

状態は 4 つ: `not_started` / `in_progress` / `generated` / `confirmed`

許可する遷移:

- `not_started -> in_progress`
- `in_progress -> generated`
- `generated -> in_progress`
- `generated -> confirmed`
- `confirmed -> in_progress`（確定解除操作のみ）

禁止: `in_progress -> confirmed` の直接遷移、`confirmed` 状態での入力値編集・再生成。

状態遷移は UI だけでなく backend service で守る。専用 mutation:

- `startMonthlyReview` / `saveMonthlyReviewInput` / `generateMonthlyReview` / `confirmMonthlyReview` / `reopenMonthlyReview`

確定済み月は、翌月の月初会員数、前月コピー、直近 3 か月平均退会率の計算基準に使う。MVP では監査ログは作らない。

### 5.3 スナップショット

月次レビューは、生成時点の計算結果をスナップショット保存する。費用マスタ、配賦ルール、退会率下限、広告投資率などを後で変更しても、過去レポートが勝手に変わらないようにする。

保存内容: 入力値、主要 KPI、PL 計算結果、LTV / 限界 CPO、重要成功要因 最大 3 つ、推奨アクション、使用した設定値のコピー。

`monthly_review_snapshot` は主要値だけカラム（total_revenue / operating_profit / ending_member_count / new_member_count / resigned_member_count / ad_spend_amount / cpo / marginal_cpo）、詳細は JSONB で持つ。再生成ごとに `version` を増やし、旧 current は `is_current = false` + `superseded_at` を設定する。

推奨アクションは、テンプレート生成後にユーザーが編集できる。編集後の文言をスナップショットに保存し、再生成時は上書きするか確認する。

## 6. 重要成功要因の判定ルール

重要成功要因は最大 3 つに絞り、ルールベースで判定する。生成 AI を使う場合も、根拠となる数値判定はルールベースで行い、文章補助に留める。

各重要成功要因には、関連 KPI、未達ギャップ、推奨アクション、検証指標を紐づける。

### 6.1 優先順位

1. 営業利益への影響額が大きいもの
2. 月末会員数未達に直結するもの
3. CPO が限界 CPO を超えているもの
4. 拠点別で赤字を生んでいるもの
5. 前月から悪化しているもの

### 6.2 営業利益未達の分解

- 営業利益未達
  - 売上不足
  - 広告費過多
  - 変動費過多
  - 固定費過多
  - 本部経費配賦後の特定拠点赤字

### 6.3 売上不足の分解

月謝売上不足を主、その他売上不足を副として扱う。

- 総売上不足
  - 月謝売上不足
    - 月末会員数不足
    - 平均月謝不足
  - その他売上不足

### 6.4 月末会員数不足の分解

1. 入会不足
2. 退会過多
3. 月初会員数不足（過去の積み上げ不足のため、当月要因としては 1, 2 を優先）

### 6.5 入会不足の判定

ファネルの上流から順に見る: 問い合わせ数 → 体験予約数 → 体験実施数 → 入会数。

- 問い合わせ数 < 目標問い合わせ数: 問い合わせ不足
- 問い合わせ不足 かつ CPO が安全ライン: 広告増額余地あり
- 問い合わせ不足 かつ CPO が注意 / 危険: 広告増額より導線改善を優先

### 6.6 退会過多の判定

- 当月退会率 > 許容退会率: 当月退会過多
- 直近 3 か月平均退会率 > 許容退会率: 構造的な退会過多
- 退会数が目標会員数達成に必要な許容退会数を超過: 会員数未達要因

### 6.7 平均月謝不足の判定

- 平均月謝 < 目標平均月謝: 平均月謝不足

重要成功要因に上げるのは、月謝売上未達への影響額が大きい場合だけとする。値上げ・プラン構成比の詳細分解までは行わず、推奨アクションは「割引、低単価プラン、上位プラン比率を確認する」程度に留める。

### 6.8 広告費過多と CPO の判定

- CPO > 限界 CPO: 広告費過多 / 獲得効率危険
- CPO > 限界 CPO × 70%: 注意
- 広告費 > 広告費上限 かつ CPO 注意以上: 広告費抑制候補
- 問い合わせ不足 かつ CPO 安全: 広告増額余地あり

CPO が悪い場合は、CPA（広告費 ÷ 問い合わせ数）と問い合わせ入会率（入会数 ÷ 問い合わせ数）に分解する。問い合わせ入会率の悪化は、体験予約率・体験実施率・入会率に分解する。

### 6.9 変動費過多の判定

- 実績変動費率 = 変動費 ÷ 対象売上
- 実績変動費率 > 設定変動費率 + 許容幅: 変動費過多
- 影響額 = 実績変動費 - 想定変動費

売上が伸びれば変動費額も増えるため、金額だけではなく率と想定差分で見る。

### 6.10 固定費過多の判定

- 固定費超過: 実績固定費 > マスタ / 予算固定費
- 固定費負担過大: 固定費 ÷ 売上 が目標固定費率を超過

重要成功要因に出すときは、営業利益未達への影響額が大きい方を優先する。

### 6.11 拠点別赤字の判定

本部経費配賦後営業利益で判定する。利益段階は、拠点直接利益 → 本部経費配賦額 → 配賦後営業利益。

- 配賦後営業利益 < 0: 拠点赤字
- 配賦後営業利益率 < 目標利益率: 利益率低下
- 直接利益は黒字だが配賦後赤字: 本部経費負担の見直し候補

## 7. レポート構成

レポートは画面表示を先行し、印刷 / PDF は後回しにする。要約中心、根拠展開可能な構成にする。

- 今月の重要成功要因 最大 3 つ
- 来月の推奨アクション
- 売上 / 営業利益 / 会員数 / CPO の予実差分カード
- 計画、CRM 実績、手入力確定値の比較
